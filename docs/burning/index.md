# 宗门焚诀

这一章不讲页面怎么画，也不讲 PWA 怎么起步，而是专门讲那些“产品一上线就绕不过去”的现实问题。

如果说前面的入门内容是在教你把小手机做出来，那么这一章就是在教你怎么给自己的小手机加门槛、加规则、加控制力。

对于 AI-Native 小手机来说，常见需求通常有这几类：

- 限定内部测试用户使用
- 付费后发放激活资格
- 区分体验版、正式版、永久版
- 控制不同角色包、剧情包、功能包的开放权限
- 在被分享、被转卖、被破解时，尽量提高成本

而“激活码”正是这类需求里最常见、也最容易最先落地的一种方案。

## 这一章会讲什么

这一章会围绕“添加激活码”这个主题，系统讲清楚下面几件事：

- 为什么小手机产品经常需要激活体系
- 纯前端激活码、半离线激活码、服务端校验激活码分别适合什么阶段
- 不同加密和签名方式分别解决什么问题
- 不同方案的破解难度、维护成本、运营灵活性有什么差别
- 如何根据你的产品阶段选择“够用但不过度”的方案

## 先给一个结论

如果你现在还在做教程 Demo、内测版本、或者个人项目，最重要的不是一上来就做出银行级安全方案，而是先搞清楚：

1. 你到底要防谁
2. 你愿意付出多少维护成本
3. 你能不能接受被少量破解
4. 你是否真的有服务端能力长期支撑

很多开发者一开始把激活码想得太简单，后来发现太容易被扒；也有人一开始把系统做得太重，结果自己维护不过来。

所以这一章的核心目标不是“神级防破解”，而是帮助你找到一个适合当前阶段的激活策略。
