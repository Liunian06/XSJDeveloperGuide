# 宗门焚诀

“宗门焚诀”这一章，讲的不是如何把页面做出来，而是当你真的开始做一个小手机产品后，那些几乎一定会迎面撞上的现实问题。

前面的“入门”板块，更偏向带你把基础跑起来，比如环境、页面、数据库这些最先动手的部分。

而“宗门焚诀”更像是进阶生存指南：当你开始把小手机从一个 Demo 往真正可用的产品推进时，你会发现，真正难的往往不是把界面搭出来，而是把各种关键问题处理稳。

这些问题通常包括：

- 如何做激活码、授权码、兑换码
- 如何控制角色包、剧情包、功能包的开放权限
- 如何处理本地缓存、用户数据、聊天记录的安全与迁移
- 如何设计付费、试用、订阅、永久授权等产品规则
- 如何降低分享、倒卖、破解、滥用的成本收益比
- 如何在纯前端、半离线、带后端三种模式之间做权衡
- 如何在“安全性、开发成本、维护成本、用户体验”之间找到平衡点

## 这一章到底是干什么的

这一章的核心定位，是帮助开发者解决“小手机开发中必然会遇到的问题”。

它不是单纯讲某一个技术点，也不是只围着激活码打转，而是专门收纳那些：

- 前期很容易忽略
- 真开始做产品时又绕不过去
- 一旦处理不好，后面就会反复返工

的关键问题与解决思路。

你可以把这一章理解成：

> 当你已经能把小手机做出来以后，接下来该怎么让它变得更可控、更可运营、更接近真实产品。

## 这一章会持续覆盖哪些方向

当前这一章先从“激活码”开始，因为它是最典型、也最容易最先遇到的一类问题。

但“宗门焚诀”不会只讲激活码，后续还会逐步覆盖例如：

- 激活码、授权码、兑换码的设计
- 账号体系与游客体系怎么取舍
- 角色内容如何分层授权
- 本地数据如何做持久化与迁移
- 聊天记录如何做隔离、加密、备份与恢复
- 不同平台上的缓存策略与数据风险
- 支付后如何发放权益
- 试用版、正式版、会员版如何拆分
- 如何降低破解和滥用带来的损失
- 如何给 AI Roleplay 产品建立更稳的运营闭环

## 为什么这一章很重要

做小手机和做普通网页 Demo 不一样。

小手机本质上是在浏览器里，用 [`HTML`](docs/guide/first-page.md) + [`JavaScript`](docs/guide/first-page.md) + [`PWA`](docs/guide/env-setup.md) 去模拟一个“像操作系统一样”的产品体验。

它里面往往会包含：

- 类似微信、QQ、抖音这样的虚拟应用
- 角色人设、聊天历史、记忆上下文
- 不同功能模块、不同内容包、不同权限层级
- 偏陪伴型、偏叙事型、偏沉浸式的持续使用场景

这就决定了你后面一定会碰到很多“不是前端页面本身”的问题，比如：

- 权限怎么管
- 数据怎么存
- 内容怎么发
- 资格怎么控
- 体验怎么稳
- 风险怎么降

而这些，正是“宗门焚诀”要解决的内容。

## 先给一个结论

如果你已经进入“宗门焚诀”这一章，说明你做的小手机项目，正在从“能跑”往“能用”甚至“能运营”走。

这时候最重要的，不是一味追求最复杂的方案，而是先想清楚：

1. 你当前真正要解决的核心问题是什么
2. 这个问题会不会在后期持续放大
3. 你现在有没有能力支撑更重的实现方式
4. 你到底是在做教程 Demo、私域产品、还是正式商业产品

所以这一章的目标，不是教你堆最重的系统，而是帮你在每一个必然会遇到的问题上，找到“当前阶段最合适”的解决方案。
